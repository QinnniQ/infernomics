Each model received the same six held-out prompts twice at temperature 0, seed 42, 128 output-token limit, and 2048 context tokens. The runner performed one unmeasured warmup per model and shuffled measured order. This is 12 attempts per model, with latency and speed denominators restricted to the 10 completed attempts. No p95 or statistical significance claim is supported. Client wall time and Ollama generation duration have different boundaries. The source tree had uncommitted implementation changes during the run; the stored `codeRevision` is the base Git commit rather than a complete source fingerprint.

Both models passed the two instruction-format attempts. Both failed the arithmetic check twice: `gemma3` answered `48`; `phi3` gave `35` and an incorrect subtraction explanation. Both extraction outputs contained the expected company and case, but wrapped the JSON in Markdown fences, violating the requested JSON-only format. The strict JSON scorer correctly recorded these as failed format-plus-value checks; it does not claim the extracted facts themselves were wrong. The business prompt hit the output limit in both repetitions for both models. Summarization, technical explanation, and business usefulness remain unscored pending human review.

The results demonstrate measurable behavior on this six-item synthetic suite, not broad superiority of either model. Different tokenizers make token/s an imperfect cross-model comparison. The older 60-attempt GPT-4o-mini API archive used different hardware, network, prompts, and timing boundaries; its numbers are contextual evidence, not rows in this local comparison.
